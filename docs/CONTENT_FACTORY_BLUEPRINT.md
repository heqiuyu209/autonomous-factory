# 内容自动化控制面蓝图（Content Factory Blueprint）

> 定位转变：从「全自动创业公司」→「一个真实产品的安全自动维护控制面」。
> 第一笔收入来自解决一个具体问题，不来自 Portfolio CEO 的 JSON 决策。

## 1. 为什么换方向

外部审查结论（2026-09）：当前仓库是「自治软件工厂概念验证器」——骨架完整（状态机 / DAG / 重试 / SQLite / 闸门 / CLI / 185 测试），但市场验证、真实编码、部署、支付、遥测、预算与 Portfolio CEO 大多是 JSON / 规则模拟。直接接生产有 P0 安全风险（LLM 生成代码在宿主机裸奔）与「假上线」风险。

方向修正：把工厂的**流程编排 + 闸门 + 审计**骨架，重定向到离钱最近的场景——**自媒体内容自动化**。用户（项目 owner）本人就是 AI 产品赛道创作者，工具可边用边验证，内容本身就是收益。

## 2. 目标用户与场景

| 用户 | 场景 | 付费点 |
|---|---|---|
| 自媒体创作者（AI 产品 / 学习干货赛道） | 选题雷达 → 内容大纲 → 初稿 → 事实核查 → 人工确认发布 | 月费订阅，省调研/初稿时间 |
| 个人开发者 / 副业者 | 产品创意验证（值得做 / 先实验 / 别做） | 按次或月费，降低瞎做的成本 |
| 多账号运营者 | 内容线组合决策（Scale 爆款 / Kill 低效） | 进阶套餐 |

第一阶段只服务**第一种用户 + 固定技术栈 + 单一部署平台 + 单一收费模式 + 单一触达渠道（自己的账号）**。

## 3. 核心闭环（模块映射）

| 现有软件工厂组件 | 内容工厂换皮 | 状态 |
|---|---|---|
| MarketScout（web 后端） | **选题雷达**：抓微博热搜 / B站 / 知乎 / Reddit / GitHub → 打分（热度、竞争、账号匹配）→ 选题清单 | 需新增源 + 评分重写 |
| PM → PRD | **选题 → 内容大纲**（标题备选、论点结构、目标人群） | 复用 PM 思路，接真实 LLM |
| 编码流水线（coder/verifier/reviewer） | **创作流水线**：初稿 Agent → 事实核查闸门（验证）→ 风格评审 → 人工确认后才发布 | 复用闸门哲学，换领域 |
| Analytics Agent | **数据回流**：阅读 / 涨粉 / 转化 → 健康度 + 推荐（Scale / Kill） | 接 OpenTelemetry 或平台 API |
| Portfolio CEO | **内容线组合决策**：多账号 / 多内容线预算分配 | 有真实数据后才启用 |
| Deployment Agent | **发布管线**：草稿 → staging → 人工批准 → 发布到平台 | 人工闸门保留 |

## 4. 阶段路线

### 阶段 0：安全修复期（约 1–2 周）——地基，不可跳过

验收标准（对应外部审查 P0/P1）：

- [ ] P0 容器化执行：LLM 生成的代码在一次性容器/沙箱运行，默认断网、只读挂载 worktree、无生产密钥、限 CPU/内存/进程数与执行时间；宿主机不再 `subprocess.run(pytest)` 裸执行
- [ ] P1 取消默认演示注错：`factory run` 默认 `seed_bug=False`，仅 `factory demo` 启用
- [ ] P1 传递完整上下文：Coder 收到 PRD、`TaskDef.description`、依赖关系与代码仓库上下文（而非仅 title）
- [ ] P1 发布闸门 fail-closed：缺失 gate 必须失败，空配置不得 `LIVE`
- [ ] P1 回滚失败退出码：`ROLLED_BACK` 时 CLI 返回非 0，CI 能感知
- [ ] P1 真实成本计费：用 OpenAI usage 记账，美元不再恒为 0；预算持久化到账户，重启不归零
- [ ] P1 超时强杀工作进程：超时后 daemon worker 必须终止，防止写回已重置的 worktree
- [ ] P1 修正 PostgreSQL 驱动：统一 psycopg2-binary 或 psycopg3，`.env.example` 与 README 对齐

### 阶段 1：单产品闭环（约 3–6 周）——内容自动化 MVP

- 只支持一种模板：「选题 + 初稿生成」流水线
- 接真实 LLM（OpenAI 后端端到端验证）
- 新增数据源适配器：微博热搜 / B站 / 知乎（替换或补充 Reddit/GitHub）
- 加入：登录、数据库迁移、支付（Stripe webhook 驱动权益）、邮件、真实部署、备份、遥测（OpenTelemetry）
- 用户（owner）真实使用 2 周，收集效率与内容反馈

### 阶段 2：半自动经营

- 系统自动：收指标、生成选题报告、跑测试、部署到 staging
- 人工保留：代码合并、生产发布、广告/推广支出（三重人工闸门）

### 阶段 3：收入跑通后开放 CEO

- 前置条件：真实付费用户、收入 > 模型与基础设施边际成本、连续留存数据
- 之后允许 Portfolio CEO 调整预算，但必须带：每日支出上限 + 总熔断器 + 审计动作执行器 + 审批流

## 5. 安全底线（不可妥协）

1. **AI 生成的执行体永不接触宿主机**：容器 / 沙箱 + 默认断网 + 只读挂载 + 无密钥
2. **发布永不静默**：内容发布与代码部署都保留人工确认闸门（沿用「评审通过才合入」哲学）
3. **支付由服务端 webhook 驱动**：不依赖支付完成跳转页面
4. **成本可审计**：真实 usage 记账，预算持久化，超限硬阻断
5. **CEO 熔断**：任何自动预算动作都有日限额与总熔断，动作可回滚

## 6. 变现模型

| 阶段 | 变现 |
|---|---|
| 0–1 | 自己账号使用 → 涨粉 / 广告 / 课程（内容即收益） |
| 1–2 | 内测订阅：向同类创作者开放（月费制） |
| 2–3 | 开源核心 + 云托管订阅 |
| 3+ | 多账号版（组合决策）+ 企业版 |

## 7. 与 ROADMAP 的关系

本蓝图是 ROADMAP V6 之后的**产品化方向**（原 ROADMAP 所述「LLM 驱动判断、真实多产品部署、组合回测」的落地形态）。代码仓库继续按小步推进：每次修改 → pytest + ruff 全绿 → 单功能提交 → 冒烟。
